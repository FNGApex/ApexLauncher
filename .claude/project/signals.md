## Cross-cutting

- **IPC type generation (complete):** `src/lib/bindings.ts` is a **committed, generated file** produced by tauri-specta (`make_builder()` / `builder.export(...)` in a `#[cfg(debug_assertions)]` block at app startup). It is the single source of truth for all Tauri commands, events, and DTOs. `src/lib/ipc.ts` is a **thin adapter** — it imports from `bindings.ts`, wraps commands via an `unwrap()` helper (restores reject-on-error), and re-exports generated DTOs under the names call sites use. `src/lib/store.ts` **imports** its task/run types from `bindings.ts` (no hand-mirrored decls). A Rust DTO/command/event change now requires **regenerating `bindings.ts`** via `scripts/build.sh dev` on Windows (start the dev window, wait for the `[bindings] exported` line, stop it) — not a manual `ipc.ts` edit. Residual specta artifacts absorbed by the adapter: `LoaderKind` erased to `string` (stays frontend-owned); `Task`/`TaskUpdatePayload` carry a `_Serialize|_Deserialize` nominal split; `AccountMeta` is surfaced as `AccountMeta_Serialize`. A Linux-only export test (`bindings_export_tests.rs`) covers future CI regeneration. Spec: `docs/spec/ts-type-generation.md`.
- **Task-queue contract:** `add_mod`, `update_mod`, `import_mrpack`, `import_curseforge_zip`, `install_modpack`, `update_modpack` all return a `u64` task id (frontend: `Promise<number>`). Results arrive asynchronously via `task://update` event when `status.kind === "done"` and `task.result` is set. `set_mod_enabled`, `remove_mod`, `set_pack_lock`, `set_instance_java` remain synchronous (instant, no task id). `enrich_instance_mods` is async but does not enqueue a task — returns result directly.
- **Zustand stores:** `src/lib/store.ts` exports `useAppStore` (tasks `Map<number,Task>`, runs `Map<string,RunState>`, runLogs `Map<string,RunLogLine[]>`) and `useUiStore` (sidebarCollapsed `boolean`, browseProvider `"curseforge"|"modrinth"`). `AppShell` is the sole `useAppStore` subscriber for event-driven updates; routes read from both stores. `useUiStore` persists `browseProvider` to remember the last-used browse tab across navigations.
- **Event channel map:** `task://progress` (per-child download progress, from `TauriTaskObserver`), `task://update` (full task snapshot per status transition, from `TauriTaskObserver`), `run://update` (run status transition, from `TauriLaunchSink`), `launch://log` / `launch://exit` (JVM stdout/stderr, from `TauriLaunchSink`), `install://log` (forge installer output, from `TauriInstallSink`), `download://progress` (raw download progress for the standalone `execute_download_plan` command, from `TauriEventSink`), `auth://device-code` (MS OAuth device code, from `TauriAuthSink`).
- **Auth commands changed:** `list_accounts`/`get_active_account_id`/`remove_account`/`set_active_account` removed; `get_account`/`logout` added. `accounts.json` → `account.json`. `Accounts.tsx` route removed; auth UI is now inline in `Sidebar.tsx`.
- **App data dir:** `<OS-appdata-base>/ApexLauncher/` resolved via `app.path().data_dir()` + join `"ApexLauncher"` in `store.rs`. macOS: `~/Library/Application Support/ApexLauncher/`. Windows: `%APPDATA%\ApexLauncher\`. Linux: `~/.local/share/ApexLauncher/`. Cache subtree: `cache/{assets,libraries,versions,java,meta,installers}`.
- **Test layout:** Unit tests live in **sibling `<stem>_tests.rs` files**, not inside the source files. Each source module ends with `#[cfg(test)] #[path = "<stem>_tests.rs"] mod tests;`. Module-scope `#[cfg(test)]` scaffolding stays in the source file. `lib_tests.rs` holds `lib.rs`'s test block. See CLAUDE.md → "Rust test layout (convention)". Total Rust lib tests: **654** — 41 download + 43 resolver + 43 java + 11 java_resolve + 46 launch + 40 auth + 20 loader_profile + 32 instances + 13 store + 9 materialize + 14 forge_installer + 41 mod_install + 35 providers + 67 curseforge + 40 modrinth + 83 modpack + 45 lib_tests + **17 task_manager** + 15 settings + 13 integration tests in `src-tauri/tests/`. No frontend tests; planned Phase 7.
- **Materialize (C2 complete):** `src-tauri/src/core/materialize.rs` — hardlink+copy-fallback; `launch_instance` calls `rewrite_classpath_for_instance` + `materialize` at step 6b. Assets stay shared in `cache/assets`; libs + version jars hardlinked into `<instances>/<slug>/`.
- **Staging/promote pattern:** `remap_to_staging(items, mc_dir, staging_dir)` + `promote_staging(staging_dir, target_dir)` defined in `core/modpack.rs` and shared by all five job types (`ImportMrpackJob`, `ImportCfZipJob`, `UpdateModpackJob`, `ModAddJob`, `ModUpdateJob`). Staging dir: `<inst_dir>/.staging-<task_id>/`. Atomic rename between staging and instance dir (same-filesystem sibling). On cancel/fail: `remove_dir_all(staging_dir)`.
- **Per-instance Java/RAM config:** `Instance.java` is `JavaCfg` (`major`, `args_override`, `memory_mb`, `min_memory_mb`, `path_override`, `use_pack_settings`). `java_resolve::resolve_effective_java(inst, settings) -> EffectiveJava` applies 3-tier precedence: (1) `inst.source.recommended` (pack-recommended, always `None` today), (2) per-instance override when `use_pack_settings == true`, (3) global `Settings` default. `set_instance_java` Tauri command persists `JavaCfg`. `validate_java_path` probes a binary and returns `JavaProbe { major, version }`.
- **Mod metadata at add-time:** `ModEntry` now carries `name: Option<String>`, `icon_url: Option<String>`, `summary: Option<String>` — captured from `ProjectSummary` at add-time. Dependency-added mods and old manifests have `None`. `enrich_instance_mods` backfills these fields for mods that are missing them (called once per session per instance via `enrichedSlugs` guard in `InstanceDetail.tsx`).
- **Pack update-check:** `Source` carries `last_update_check: Option<String>`, `latest_version: Option<String>`, `latest_version_id: Option<String>`. `refresh_pack_meta` (Tauri command) checks once per 24h (throttled by `needs_update_check`), writes results to the instance manifest, and returns `PackMetaRefresh { update_available, latest_version, checked }`. Called from `InstanceDetail.tsx` once per session per managed instance via `refreshedSlugs` guard.
- **Browse per-provider split:** `/browse` redirects to `/browse/:provider` (last-used provider from `useUiStore`). `BrowseProvider` component reads `:provider` param; sidebar shows CurseForge, Modrinth as clickable nav items + FTB, ATLauncher as "coming soon" static items. `/browse/:provider/:id` → `BrowsePackInfo` detail page (lazy `get_pack_info`, version-select modal, install button). `installedIndex.ts` builds a `Map<string,slug>` from installed instances to show "Installed" pills.
- **Conventions pointer:** folder/domain conventions live in `.claude/project/signals/*.md`; regenerate with `/refresh-signals`.
- **Deterministic substrate:** `.claude/project/deterministic-signals.md`
- **Domain partitioning basis:** partitioned by functional workflow — instance lifecycle, metadata fetching, download execution, task queue orchestration, vanilla resolution, Java management, launch orchestration, Microsoft auth, and UI shell are orthogonal concerns that change independently. `src-tauri/src/lib.rs` is the Tauri command dispatch layer shared across all domains; job implementations (`ImportMrpackJob`, `ModAddJob`, etc.) live there because they require `AppHandle` for Tauri state access.
- **task-manager domain:** `src-tauri/src/core/task_manager.rs` is the serial FIFO worker; job impls live in `lib.rs`; frontend surface in `store.ts` + `DownloadManager.tsx` + `AppShell.tsx`.
- **Baked CF API key tier:** `src-tauri/build.rs` parses gitignored `src-tauri/.env` for `MODLOADER_CF_API_KEY` and bakes it via `cargo:rustc-env`. Missing `.env` bakes nothing; build always succeeds. Spec: `docs/spec/curseforge-api-key.md`.
- **Settings new fields (ui-overhaul):** `sidebar_start_collapsed: bool` (initial seed for sidebar; live state in `useUiStore`), `auto_download_java: bool` (default true; when false, launch aborts instead of downloading), `show_console_default: bool` (default false; seeds console expand state in InstanceDetail), `keep_launcher_open: bool` (default true; minimize vs keep open after launch), `maximize_on_start: bool` (default true; replaces static tauri.conf.json maximized flag).

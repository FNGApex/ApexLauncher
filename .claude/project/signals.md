## Cross-cutting

- **IPC type generation (complete):** `src/lib/bindings.ts` is a **committed, generated file** produced by tauri-specta (`make_builder()` / `builder.export(...)` in a `#[cfg(debug_assertions)]` block at app startup). It is the single source of truth for all Tauri commands, events, and DTOs. `src/lib/ipc.ts` is a **thin adapter** — it imports from `bindings.ts`, wraps commands via an `unwrap()` helper (restores reject-on-error), and re-exports generated DTOs under the names call sites use. `src/lib/store.ts` **imports** its task/run types from `bindings.ts` (no hand-mirrored decls). A Rust DTO/command/event change now requires **regenerating `bindings.ts`** via `scripts/build.sh dev` on Windows (start the dev window, wait for the `[bindings] exported` line, stop it) — not a manual `ipc.ts` edit. Residual specta artifacts absorbed by the adapter: `LoaderKind` erased to `string` (stays frontend-owned); `Task`/`TaskUpdatePayload` carry a `_Serialize|_Deserialize` nominal split; `AccountMeta` is surfaced as `AccountMeta_Serialize`. A Linux-only export test (`bindings_export_tests.rs`) covers future CI regeneration. Spec: `docs/spec/ts-type-generation.md`.
- **Task-queue contract:** `add_mod`, `update_mod`, `import_mrpack`, `import_curseforge_zip`, `install_modpack` (all providers including FTB and ATLauncher), `update_modpack` all return a `u64` task id (frontend: `Promise<number>`). Results arrive asynchronously via `task://update` event when `status.kind === "done"` and `task.result` is set. `set_mod_enabled`, `remove_mod`, `set_pack_lock`, `set_instance_java`, `set_pending_launch_warning_suppressed`, `set_instance_icon`, `clear_instance_icon` remain synchronous (instant, no task id). `enrich_instance_mods` is async but does not enqueue a task — returns result directly. `rescan_pending_manual`, `import_manual_file` are synchronous (instant local ops, return remaining `Vec<PendingManual>`). `start_pending_watch`, `stop_pending_watch` are synchronous lifecycle commands for the `PendingWatcher` managed state. `update_modpack` for FTB and ATLauncher providers returns a string error ("not supported yet") immediately without enqueueing a task.
- **Zustand stores:** `src/lib/store.ts` exports `useAppStore` (tasks `Map<number,Task>`, runs `Map<string,RunState>`, runLogs `Map<string,RunLogLine[]>`) and `useUiStore` (sidebarCollapsed `boolean`, browseProvider `"curseforge"|"modrinth"|"ftb"|"atlauncher"`). `AppShell` is the sole `useAppStore` subscriber for event-driven updates; routes read from both stores. `useUiStore` persists `browseProvider` to remember the last-used browse tab across navigations.
- **Event channel map:** `task://progress` (per-child download progress, from `TauriTaskObserver`), `task://update` (full task snapshot per status transition, from `TauriTaskObserver`), `run://update` (run status transition, from `TauriLaunchSink`), `launch://log` / `launch://exit` (JVM stdout/stderr, from `TauriLaunchSink`), `install://log` (forge installer output, from `TauriInstallSink`), `download://progress` (raw download progress for the standalone `execute_download_plan` command, from `TauriEventSink`), `auth://device-code` (MS OAuth device code, from `TauriAuthSink`), `manual://resolved` (`ManualResolvedPayload { slug, resolved: Vec<ResolvedManual>, remaining: u32 }` — emitted by `PendingWatcher` debounced notify watch on instance `mods/` dir, and by `rescan_pending_manual` / `import_manual_file` after each reconcile; AppShell invalidates `["instance", slug]` on receipt).
- **Auth commands changed:** `list_accounts`/`get_active_account_id`/`remove_account`/`set_active_account` removed; `get_account`/`logout` added. `accounts.json` → `account.json`. `Accounts.tsx` route removed; auth UI is now inline in `Sidebar.tsx`.

Module-scope `#[cfg(test)]` scaffolding stays in the source file. `lib_tests.rs` holds `lib.rs`'s test block. See CLAUDE.md → "Rust test layout (convention)". - **Staging/promote pattern:** `remap_to_staging(items, mc_dir, staging_dir)` + `promote_staging(staging_dir, target_dir)` defined in `core/modpack.rs` and shared by all seven job types (`ImportMrpackJob`, `ImportCfZipJob`, `ImportFtbJob`, `ImportAtlJob`, `UpdateModpackJob`, `ModAddJob`, `ModUpdateJob`). Staging dir: `<inst_dir>/.staging-<task_id>/`. Atomic rename between staging and instance dir (same-filesystem sibling). On cancel/fail: `remove_dir_all(staging_dir)`.
- **Per-instance Java/RAM config:** `Instance.java` is `JavaCfg` (`major`, `args_override`, `memory_mb`, `min_memory_mb`, `path_override`, `use_pack_settings`). `java_resolve::resolve_effective_java(inst, settings) -> EffectiveJava` applies 3-tier precedence: (1) `inst.source.recommended` (pack-recommended — populated for FTB instances from `FtbVersionManifest.specs.recommended`; for ATL instances from `manifest.memory > 0`), (2) per-instance override when `use_pack_settings == true`, (3) global `Settings` default. `set_instance_java` Tauri command persists `JavaCfg`. `validate_java_path` probes a binary and returns `JavaProbe { major, version }`.
- **Mod metadata at add-time:** `ModEntry` now carries `name: Option<String>`, `icon_url: Option<String>`, `summary: Option<String>` — captured from `ProjectSummary` at add-time. Dependency-added mods and old manifests have `None`. `enrich_instance_mods` backfills these fields for mods that are missing them (called once per session per instance via `enrichedSlugs` guard in `InstanceDetail.tsx`).
- **Pack update-check:** `Source` carries `last_update_check: Option<String>`, `latest_version: Option<String>`, `latest_version_id: Option<String>`. `refresh_pack_meta` (Tauri command) checks once per 24h (throttled by `needs_update_check`), writes results to the instance manifest, and returns `PackMetaRefresh { update_available, latest_version, checked }`. Called from `InstanceDetail.tsx` once per session per managed instance via `refreshedSlugs` guard.
- **Browse per-provider split:** `/browse` redirects to `/browse/:provider` (last-used provider from `useUiStore`). `BrowseProvider` component reads `:provider` param; sidebar shows CurseForge, Modrinth, FTB, ATLauncher as clickable `<NavLink>` items (all four real; no more "coming soon"). FTB Browse: keyless, search ignores facets (filters popover hidden), empty query returns featured+popular feed (deduped, N+1 detail fetch); term search uses `/public/modpack/search/{limit}?term=...`. - **Domain partitioning basis:** partitioned by functional workflow — instance lifecycle, metadata fetching, download execution, task queue orchestration, vanilla resolution, Java management, launch orchestration, Microsoft auth, and UI shell are orthogonal concerns that change independently. `src-tauri/src/lib.rs` is the Tauri command dispatch layer shared across all domains; job implementations (`ImportMrpackJob`, `ModAddJob`, etc.) live there because they require `AppHandle` for Tauri state access.
- **task-manager domain:** `src-tauri/src/core/task_manager.rs` is the serial FIFO worker; job impls live in `lib.rs`; frontend surface in `store.ts` + `DownloadManager.tsx` + `AppShell.tsx`.

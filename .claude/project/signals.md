**Always build/test via `scripts/build.sh`** — the single cross-platform entrypoint. On **WSL** it mirrors the source onto the native Windows FS (`C:\Users\drgor\Documents\GitHub\ApexLauncher`) and builds there with `scripts/apex-build.bat` (native NTFS → incremental compilation works; no `\\wsl.localhost` UNC, no GTK blocker). On **macOS/Linux** it builds natively in place. Do not call `cargo`/`npm` directly for build/test. WSL-native is still fine for formatting (`rustfmt --edition 2021`).

No CI configuration exists yet (planned Phase 7).

## Cross-cutting

- **IPC type generation (complete):** `src/lib/bindings.ts` is a **committed, generated file** produced by tauri-specta (`make_builder()` / `builder.export(...)` in a `#[cfg(debug_assertions)]` block at app startup). It is the single source of truth for all 35 Tauri commands, 8 event channels, and all DTOs. `src/lib/ipc.ts` is a **thin adapter** — it imports from `bindings.ts`, wraps commands via an `unwrap()` helper (restores reject-on-error), and re-exports generated DTOs under the names call sites use. `src/lib/store.ts` **imports** its task/run types from `bindings.ts` (no hand-mirrored decls). A Rust DTO/command/event change now requires **regenerating `bindings.ts`** via `scripts/build.sh dev` on Windows (start the dev window, wait for the `[bindings] exported` line, stop it) — not a manual `ipc.ts` edit. Residual specta artifacts absorbed by the adapter: `LoaderKind` erased to `string` (stays frontend-owned); `Task`/`TaskUpdatePayload` carry a `_Serialize|_Deserialize` nominal split; `AccountMeta` is surfaced as `AccountMeta_Serialize`. A Linux-only export test (`bindings_export_tests.rs`) covers future CI regeneration. Spec: `docs/spec/ts-type-generation.md`.
- **Task-queue contract:** `add_mod`, `update_mod`, `import_mrpack`, `import_curseforge_zip`, `install_modpack`, `update_modpack` all return a `u64` task id (frontend: `Promise<number>`). Results arrive asynchronously via `task://update` event when `status.kind === "done"` and `task.result` is set. `set_mod_enabled`, `remove_mod`, `set_pack_lock` remain synchronous (instant, no task id).
- **Zustand store is now active:** `src/lib/store.ts` holds `tasks` (Map<number, Task>) and `runs` (Map<string, RunState>) + `runLogs`. `AppShell` is the sole subscriber — routes read from the store, never subscribe to events directly.
- **Event channel map:** `task://progress` (per-child download progress, from `TauriTaskObserver`), `task://update` (full task snapshot per status transition, from `TauriTaskObserver`), `run://update` (run status transition, from `TauriLaunchSink`), `launch://log` / `launch://exit` (JVM stdout/stderr, from `TauriLaunchSink`), `install://log` (forge installer output, from `TauriInstallSink`), `download://progress` (raw download progress for the standalone `execute_download_plan` command, from `TauriEventSink`), `auth://device-code` (MS OAuth device code, from `TauriAuthSink`).
- **Auth commands changed:** `list_accounts`/`get_active_account_id`/`remove_account`/`set_active_account` removed; `get_account`/`logout` added. `accounts.json` → `account.json`. `Accounts.tsx` route removed; auth UI is now inline in `Sidebar.tsx`.
- **App data dir:** `<OS-appdata-base>/ApexLauncher/` resolved via `app.path().data_dir()` + join `"ApexLauncher"` in `store.rs`. macOS: `~/Library/Application Support/ApexLauncher/`. Windows: `%APPDATA%\ApexLauncher\`. Linux: `~/.local/share/ApexLauncher/`. Cache subtree: `cache/{assets,libraries,versions,java,meta,installers}`.
- **Test layout:** Unit tests live in **sibling `<stem>_tests.rs` files**, not inside the source files. Each source module ends with `#[cfg(test)] #[path = "<stem>_tests.rs"] mod tests;`. Module-scope `#[cfg(test)]` scaffolding stays in the source file. `lib_tests.rs` holds `lib.rs`'s test block. See CLAUDE.md → "Rust test layout (convention)". Total Rust lib tests: **505** — 37 download + 43 resolver + 39 java + 36 launch + 40 auth + 20 loader_profile + 18 instances + 13 store + 8 materialize + 14 forge_installer + 40 mod_install + 89 providers + 79 modpack + 18 lib_tests + **11 task_manager** + 10 integration tests in `src-tauri/tests/`. No frontend tests; planned Phase 7.
- **Materialize (C2 complete):** `src-tauri/src/core/materialize.rs` — hardlink+copy-fallback; `launch_instance` calls `rewrite_classpath_for_instance` + `materialize` at step 6b. Assets stay shared in `cache/assets`; libs + version jars hardlinked into `<instances>/<slug>/`.
- **Staging/promote pattern:** `remap_to_staging(items, mc_dir, staging_dir)` + `promote_staging(staging_dir, target_dir)` defined in `core/modpack.rs` and shared by all five job types (`ImportMrpackJob`, `ImportCfZipJob`, `UpdateModpackJob`, `ModAddJob`, `ModUpdateJob`). Staging dir: `<inst_dir>/.staging-<task_id>/`. Atomic rename between staging and instance dir (same-filesystem sibling). On cancel/fail: `remove_dir_all(staging_dir)`.
- **Conventions pointer:** folder/domain conventions live in `.claude/project/signals/*.md`; regenerate with `/refresh-signals`.
- **Deterministic substrate:** `.claude/project/deterministic-signals.md`
- **Domain partitioning basis:** partitioned by functional workflow — instance lifecycle, metadata fetching, download execution, task queue orchestration, vanilla resolution, Java management, launch orchestration, Microsoft auth, and UI shell are orthogonal concerns that change independently. `src-tauri/src/lib.rs` is the Tauri command dispatch layer shared across all domains; job implementations (`ImportMrpackJob`, `ModAddJob`, etc.) live there because they require `AppHandle` for Tauri state access.
- **task-manager domain:** `src-tauri/src/core/task_manager.rs` is the serial FIFO worker; job impls live in `lib.rs`; frontend surface in `store.ts` + `DownloadManager.tsx` + `AppShell.tsx`.
- **Baked CF API key tier:** `src-tauri/build.rs` parses gitignored `src-tauri/.env` for `MODLOADER_CF_API_KEY` and bakes it via `cargo:rustc-env`. Missing `.env` bakes nothing; build always succeeds. Spec: `docs/spec/curseforge-api-key.md`.

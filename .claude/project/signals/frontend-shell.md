# frontend-shell

## Overview

React 19 app entry, routing, sidebar navigation (collapsible, inline login/logout, DownloadManager toggle), IPC adapter layer (`ipc.ts` over `bindings.ts`), Zustand stores (`useAppStore` for task/run state, `useUiStore` for UI state), TanStack Query client, tabbed instance detail (Info/Modlist/Tech/Java via React Router `<Outlet>`), per-provider Browse split (CurseForge/Modrinth/FTB/ATLauncher — all four live), `BrowsePackInfo` detail page, theme system (dark/light/system), custom instance icons. `AppShell` mounts once, subscribes to all event channels, hydrates store on startup. No standalone Accounts route — auth UI in Sidebar.

## Coupling

- `bindings.ts` is generated from Rust; a Rust DTO/command/event change requires regenerating via `scripts/build.sh dev` on Windows. `ipc.ts` has zero hand-declared IPC interfaces.
- `InstanceDetail.tsx` passes `InstanceTabContext` to all four tab children via React Router `<Outlet context={...}>`. Tabs use `useOutletContext<InstanceTabContext>()`.
- Task/run event subscriptions live exclusively in `AppShell` (mount-once); routes read from Zustand store. This is the authoritative pattern.
- `InfoTab` starts `PendingWatcher` via `startPendingWatch` on mount; `AppShell` subscribes to `events.manualResolved` and invalidates the instance query. Both wiring points required.
- Drag-drop in `InfoTab` uses `getCurrentWebviewWindow().onDragDropEvent`; only `.jar` drops forwarded to `importManualFile`; cleanup returned from `useEffect`.
- `ModlistTab` is a thin wrapper over `ManageInstallsPanel` from `InstanceDetail.tsx` — changes only need to touch `InstanceDetail.tsx`.
- `enrichedSlugs` and `refreshedSlugs` are module-level `Set<string>` in `InstanceDetail.tsx` — gate once-per-session calls regardless of remount.

## Conventions

- Path alias `@/` maps to `src/`.
- `cn` from `src/lib/utils.ts` is the standard class composition helper.
- Theme: dark is the default (no class on `<html>`); light mode adds `.light`. Never use `dark:` Tailwind utilities.
- `install://log` has no `instanceId`; `AppShell` attributes all installer lines to whichever run has status `"preparing"`.
- `buildInstalledIndex` keys: `"modrinth"`, `"curseforge"`, `"ftb"`, `"atlauncher"` (lowercase). FTB IDs are numeric strings; ATL IDs are pack name slugs.
- `BrowseProvider` resets filters to `EMPTY_FILTERS` when `:provider` param changes.
- `ProviderKind` response value `"curseForge"` (camelCase from serde) vs routing param `"curseforge"` (lowercase) are distinct. `"ftb"` and `"atlauncher"` are the same in both forms.

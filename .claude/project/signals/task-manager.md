# task-manager

## Overview

Serial FIFO `TaskManager` (Approach C): one worker tokio task drains an unbounded `mpsc` channel, runs each `TaskJob` to a terminal status before picking up the next. Snapshot (`Arc<RwLock<Vec<Task>>>`) is the shared read surface; the worker (via `TaskContext`) is the sole writer. Per-task `CancelToken` trips running downloads and short-circuits queued tasks.

`TaskKind`: `Synthetic` (tests), `PackInstall`, `PackUpdate`, `ModAdd`, `ModUpdate`. `TaskStatus` states: `Queued → Planning → Downloading → Applying → Done | Failed | Cancelled`. `finish_done_with_result` attaches a `serde_json::Value` result payload before the `Done` transition; `task://update` event carries both the terminal status and the payload.

## Coupling

- `download` domain — `TaskContext.cancel_token()` returns a `CancelToken` from `download::CancelToken`.
- `modpack` domain — `ImportMrpackJob`, `ImportCfZipJob`, `ImportFtbJob`, `ImportAtlJob`, `UpdateModpackJob` are `TaskJob` impls in `lib.rs`.
- `mod-install` domain — `ModAddJob`, `ModUpdateJob` are `TaskJob` impls in `lib.rs`.
- `launcher-import` domain — `ImportExternalJob` is a `TaskJob` impl in `lib.rs`.
- `frontend-shell` — `AppShell` subscribes to events and drives the `tasks` slice; `Toasts` fires on Done tasks with a `result`.

## Conventions

- Lock discipline: `TaskContext` mutators take the write lock synchronously, mutate, drop the lock, then call the observer — no lock held across `.await`.
- Worker serializes tasks: `spec.job.run(&ctx).await` must complete before `rx.recv()` again. Jobs must not `tokio::spawn` sub-tasks that outlive `run()`.
- `TaskManager` is `Clone` — all clones share the same snapshot, id counter, cancel-token table, and worker channel.
- `finish_done_with_result` writes result into snapshot first, then transitions to `Done`, then notifies observer — so `task://update` always carries both.
- `Synthetic` kind is test-only; the worker does not special-case it.

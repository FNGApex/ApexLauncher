## Project overview

Lightweight cross-platform **Minecraft** mod launcher (PrismLauncher-like). Imports modpacks
from **CurseForge, Modrinth, FTB, ATLauncher**, and existing instances from
**Prism / MultiMC / PolyMC**.

- **Frontend:** React 19 + TypeScript + Vite 7 + Tailwind v4 + React Router + TanStack Query + Zustand
- **Backend:** Rust via **Tauri 2** (downloads, instances, Java, launch, auth)
- **Targets:** Windows, macOS, Linux
- **Bundle id:** `com.apex.apexlauncher`
- **Auth:** single persistent Microsoft account (keyring refresh token + `account.json`); no multi-account
- **Data root:** `<OS-appdata-base>/ApexLauncher/` (Tauri `path().data_dir()` + join, independent of bundle id) — `instances/` (per-instance trees) + `cache/{assets,libraries,versions,java,meta,installers}` (shared, dedup)

Design docs in `docs/`: `ARCHITECTURE.md` (subsystems, on-disk layout, data model, IPC),
`ROADMAP.md` (8 phases), `PROVIDERS.md` (CurseForge & Modrinth API specifics).

**External constraints:**
- CurseForge needs a free `x-api-key`; Modrinth needs none. Key resolves
  env (`MODLOADER_CF_API_KEY`) → `settings.curseforge_api_key` → baked → `None`.
  `build.rs` bakes the baked tier from a gitignored `src-tauri/.env` (missing `.env` builds fine,
  bakes nothing). Users override under Settings → Advanced → API Keys.
  **Never commit the key — repo is public.**
- Some CF mods set `allowModDistribution:false` → can't be auto-downloaded; UI opens the
  project page for manual drop-in. Shapes the pack resolver.

## Build & run

**Build/test only through `scripts/build.sh`** — the single cross-platform entrypoint. Never call
`cargo`/`npm` directly for a build (CI is the only exception, below).

```bash
scripts/build.sh check               # cargo check + tsc --noEmit (both sides)
scripts/build.sh test                # full Rust test suite
scripts/build.sh test core::download # forward a cargo test filter
scripts/build.sh build               # installable bundle (tauri build)
scripts/build.sh bundle msi nsis     # only named installer formats
scripts/build.sh dev                 # dev window, HMR
```

**Windows build prereq:** bundler needs the VS2022 "Desktop development with C++" workload
(MSVC v143 + Windows SDK → `rc.exe` for `tauri-winres`). `apex-build.bat` self-sources
`vcvarsall.bat` so any shell works. MSI also needs the VBSCRIPT optional Windows feature.
See `docs/spec/phase7-installers.md`.

**CI exception:** GitHub Actions (`.github/workflows/test.yml` + `bundle.yml`) call
`cargo`/`npm`/`tauri` directly on native runners — `build.sh`'s WSL mirror is dead weight there
and `apex-build.bat` hardcodes this dev machine. `test.yml` gates PRs (ubuntu) + push-to-main
(3-OS); `bundle.yml` builds installers on `v*` tags / dispatch. See `docs/spec/ci-pipeline.md`.

**On WSL:** `build.sh` rsync-mirrors the source onto native NTFS at
`C:\Users\drgor\Documents\GitHub\ApexLauncher` (excluding `target/`, `node_modules/`, `.git/`,
`gen/`, worktrees, scratch) and builds there via `apex-build.bat` with the Windows toolchain
(`C:\Users\drgor\.cargo\bin\cargo.exe` + `C:\Program Files\nodejs`). We don't build inside WSL
(no GTK/WebKit; Windows uses WebView2) and no longer build over the `\\wsl.localhost` UNC path
(native NTFS keeps incremental compilation). WSL-native is fine for non-build tasks like
`rustfmt --edition 2021 <files>`.

**On macOS / Linux:** `build.sh` builds natively in place (Linux needs GTK/WebKit dev libs,
macOS needs Xcode CLT). Same mode vocabulary.

### Rust test layout

Source files (`src-tauri/src/**/*.rs`) hold no inline `mod tests {…}`. Unit tests live in a
sibling `<stem>_tests.rs`, wired from the source module's tail:

```rust
#[cfg(test)]
#[path = "<stem>_tests.rs"]
mod tests;
```

Tests stay unit tests — the sibling compiles as a child module, so `use super::*;` and private
access keep working with no `pub`-leaking.

- New test for an existing module → its `<stem>_tests.rs` (create sibling + stub if absent).
- Shared scaffolding reachable across modules (mock sinks like `CapturingSink`, helpers like
  `read_manifest_pub`) stays at module scope under `#[cfg(test)]` in the source file — it's
  `pub` + cross-referenced, so it can't move into a child `tests` module.
- True cross-crate integration tests (public API only) → `src-tauri/tests/*.rs`.

Networking is in Rust (`reqwest`, **rustls-tls** — no OpenSSL dep). All version/loader/provider
metadata flows through `core/`, disk-cached under `<appdata>/ApexLauncher/cache/meta/`.
